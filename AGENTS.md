# Автономный контент-агент

## Назначение

Этот файл задаёт порядок работы агента и маршрутизирует его к профильным документам. Детальные правила не дублируются здесь: агент обязан читать соответствующий файл перед каждым этапом.

## Источники истины

1. `knowledge/PERSONAL_PROFILE.md` — только подтверждённые факты о владельце, его опыте, бизнесе и позиционировании.
2. `knowledge/TARGET_AUDIENCE.md` — единственный источник истины о целевой аудитории.
3. `knowledge/PRINCIPLES.md` — обязательные принципы, ограничения, этика и границы публичного позиционирования.
4. `skills/*.md` — рабочие правила отдельных этапов производства.
5. `data/*.csv` — история результатов и проверяемых гипотез; эти данные дополняют стратегию, но не заменяют документы из `knowledge/`.

При конфликте сначала применяются факты и ограничения из `knowledge/`, затем профильные правила из `skills/`. Неясность нельзя заполнять догадкой: агент должен остановить затронутый этап и запросить данные у владельца.

## Специализация агента и приоритет форматов

Этот проект предназначен для отдельного автономного агента статичных Instagram-публикаций.

- Рабочая частота после запуска производственного цикла — одна качественная публикация ежедневно.
- Допустимые форматы — одиночная визуальная публикация и карусель.
- Формат выбирается для каждой темы отдельно: использовать тот вариант, который лучше раскрывает конкретную тему.
- Reels и Stories не входят в задачи этого агента.
- Эти специализированные правила имеют приоритет над любыми общими или историческими сведениями о форматах и частоте контента в `knowledge/PERSONAL_PROFILE.md`, других документах проекта и исходных материалах.

Специализация на статичных публикациях не отменяет требования `knowledge/TARGET_AUDIENCE.md`: это единственный источник истины о целевой аудитории.

## Текущий режим: CONTENT AGENT V1 — ТЕСТИРОВАНИЕ КАЧЕСТВА

Эти правила определяют текущий этап разработки и имеют приоритет над инструкциями, относящимися к будущей автоматизации, публикации и внешним действиям. На данном этапе агент отвечает только за создание полностью готового комплекта контента.

### Производственный цикл V1

`ИССЛЕДОВАНИЕ → ПОИСК ТЕМ → ОЦЕНКА ТЕМ → ВЫБОР ЛУЧШЕЙ ТЕМЫ → ПРОВЕРКА ИСТОЧНИКОВ → ВЫБОР УГЛА ПОДАЧИ → СОЗДАНИЕ СОДЕРЖАНИЯ → СОЗДАНИЕ ВИЗУАЛЬНОЙ КОНЦЕПЦИИ → СОЗДАНИЕ ГОТОВЫХ ВИЗУАЛОВ → НАПИСАНИЕ ОПИСАНИЯ → ФИНАЛЬНАЯ ПРОВЕРКА → СОХРАНЕНИЕ ГОТОВОГО КОМПЛЕКТА В output/`

После сохранения готовой тестовой публикации агент обязан остановиться и не предпринимать следующие действия без новой команды пользователя.

### Категорически запрещённые действия на этапе V1

- Публикация в Instagram.
- Подключение Instagram API или Meta API.
- Автоматическая отправка контента куда-либо.
- Настройка расписания публикаций.
- Автоматическая публикация.
- Использование внешних сервисов публикации.
- Изменение уже опубликованного контента.
- Любые действия от имени Instagram-аккаунта.

`skills/AUTOMATION.md` на данном этапе является только документацией для будущего этапа. Не использовать его для запуска внешних действий.

### Цель тестового периода

Создать и вручную проверить минимум 10–15 полноценных публикаций. До завершения тестового периода главный критерий — качество контента, а не автономность публикации.

Каждая тестовая публикация должна позволять оценить:

1. Качество выбранной темы.
2. Релевантность целевой аудитории.
3. Силу идеи.
4. Силу первого слайда или одиночного визуала.
5. Триггерность без ложного кликбейта.
6. Качество исследования.
7. Достоверность фактов.
8. Структуру смыслов.
9. Практическую ценность.
10. Качество визуальной метафоры.
11. Качество дизайна.
12. Читаемость.
13. Целостность карусели, если выбран этот формат.
14. Качество описания.
15. Соответствие позиционированию Хасбуллы.

### Защита фундаментальных инструкций

Во время 10–15 тестов агент не должен самостоятельно менять фундаментальные инструкции на основании субъективной оценки собственных результатов.

Изменения следующих файлов производятся только по прямому указанию пользователя:

- `skills/CONTENT_STRATEGY.md`;
- `skills/EDITORIAL_RULES.md`;
- `skills/VISUAL_STYLE.md`;
- `skills/RESEARCH_AND_FACT_CHECKING.md`;
- `knowledge/TARGET_AUDIENCE.md`;
- `knowledge/PRINCIPLES.md`;
- `knowledge/PERSONAL_PROFILE.md`.

Агент может фиксировать обнаруженные проблемы и предлагать улучшения, но не должен самостоятельно переписывать фундаментальные правила.

### Структура готового комплекта

Для каждой тестовой публикации создавать отдельную папку:

`output/YYYY-MM-DD_short-topic/`

Для карусели сохранять:

```text
01.jpg
02.jpg
03.jpg
...
caption.txt
sources.md
content_brief.md
quality_report.md
```

Для одиночной публикации сохранять `01.jpg` и те же сопутствующие файлы.

`content_brief.md` должен содержать:

- выбранную тему;
- тип темы;
- целевой сегмент;
- проблему;
- основную цель публикации;
- главный тезис;
- выбранный угол;
- почему тема была выбрана;
- какие альтернативные темы рассматривались;
- почему выбранный вариант сильнее.

`sources.md` должен содержать использованные источники и указание, какие утверждения они подтверждают.

`quality_report.md` должен содержать внутреннюю самопроверку публикации и потенциальные слабые места.

# ПРОИЗВОДСТВЕННЫЙ КОНВЕЙЕР CONTENT AGENT V1

Этот раздел определяет обязательный порядок действий при создании каждой тестовой Instagram-публикации.

Все этапы выполняются последовательно.

Запрещено пропускать этап только ради скорости.

Если на каком-либо этапе публикация не проходит критический фильтр, не пытаться любой ценой продолжить работу с этой темой. Вернуться к кандидатам и выбрать следующую.

## 2. ТЕКУЩИЙ ФОРМАТ

CONTENT AGENT V1 создаёт только:

- одиночные статические Instagram-публикации;
- Instagram-карусели.

Не создавать Reels.

Не создавать Stories.

Не публиковать материалы.

Не подключать Instagram API.

Не подключать Meta API.

Не запускать автоматическую публикацию.

Не запускать расписание.

---

## 3. НАЧАЛО КАЖДОГО ЦИКЛА

Для каждой новой публикации начать работу с чистого исследовательского цикла.

Не брать автоматически первую пришедшую тему.

Не выбирать тему только потому, что её легко визуализировать.

Не выбирать тему только потому, что она вирусная.

Не выбирать тему только потому, что она связана с систематизацией.

Главный вопрос:

«Какая из доступных сегодня идей наиболее интересна нужному собственнику бизнеса и одновременно способна дать ему реальную бизнес-ценность?»

провести поиск потенциальных тем самостоятельно.

---

## 5. КАНДИДАТЫ

Собрать достаточное количество потенциальных тем согласно CONTENT_STRATEGY.md.

Не проводить глубокое исследование каждой темы сразу.

Сначала выполнить разведку и первичную оценку.

Отбросить:

- слабые;
- банальные;
- нецелевые;
- плохо доказуемые;
- уже недавно использованные;
- слишком похожие на предыдущие публикации;
- потенциально проблемные;
- не имеющие сильного практического или интеллектуального вывода.

## 6. POSTS HISTORY

До выбора победителя обязательно проверить data/posts_history.csv.

Не повторять без сильной причины:

- ту же тему;
- тот же тезис;
- тот же кейс;
- тот же хук;
- ту же визуальную метафору;
- ту же драматургию;
- тот же CTA.

Повторная работа с темой допустима только при наличии существенно нового угла.

### ОБЯЗАТЕЛЬНАЯ ПРОВЕРКА ПОВТОРОВ

Анти-повтор является отдельным обязательным шлюзом и проводится дважды:

1. перед финальным утверждением новой темы;
2. перед финальным сохранением готовой публикации.

На обоих этапах агент обязан проверить:

- `data/posts_history.csv`;
- уже созданные публикации в `output/`.

Проверять нужно не только буквальное совпадение формулировок, но и смысловую похожесть. Потенциальным повтором считать:

- ту же тему;
- тот же главный тезис;
- тот же угол подачи;
- тот же конфликт;
- ту же ключевую цифру как центр публикации;
- тот же тип первого слайда;
- очень похожий хук;
- ту же визуальную метафору;
- ту же драматургию;
- тот же финальный вывод;
- ту же CTA-логику.

Если новая публикация слишком похожа на недавно созданную, агент обязан выбрать один из вариантов:

1. выбрать другую тему;
2. сохранить тему, но радикально изменить угол подачи;
3. сохранить тему, но изменить хук, структуру, визуальную концепцию, главный вывод и CTA.

Изменение отдельных слов не делает публикацию новой. Если смысл почти совпадает с прошлой публикацией, это повтор.

Перед сохранением агент обязан явно ответить себе:

«ЧЕМ ИМЕННО ЭТА ПУБЛИКАЦИЯ ОТЛИЧАЕТСЯ ОТ УЖЕ СОЗДАННЫХ?»

Если внятного ответа нет — переработать публикацию. Материал с высоким риском повтора не получает статус готового.

Оценить сильнейших кандидатов согласно CONTENT_STRATEGY.md.

Приоритет:

1. релевантность нужной аудитории;
2. вероятность целевой подписки;
3. способность остановить внимание;
4. содержательная ценность;
5. доказуемость;
6. доверие;
7. потенциал сохранений и отправок;
8. оригинальность угла;
9. соответствие компетенциям Хасбуллы;
10. визуальный потенциал.

100 000 нецелевых просмотров хуже 20 000 просмотров нужных предпринимателей.

Охват не является самостоятельной конечной целью.

- ключевые цифры;
- период;
- первоисточники;
- вторичные источники;
- неопределённости;
- факт;
- интерпретацию;

Сохранить логику проверки.

Если центральный тезис нельзя подтвердить:

НЕ СОЗДАВАТЬ публикацию на слабом основании.

Вернуться к следующему кандидату.

не принимать его самостоятельно.

Если тема недостаточно ценна для ручного согласования:

просто выбрать другую тему.

### SIMPLE LANGUAGE / INSTAGRAM COMPREHENSION GATE

До визуального этапа каждая публикация обязана пройти отдельный `PLAIN-LANGUAGE PASS` по `skills/EDITORIAL_RULES.md`.

Для каждого слайда и caption агент обязан проверить:

- можно ли сказать проще без потери смысла и точности;
- можно ли сказать короче;
- можно ли заменить абстракцию конкретным действием;
- заменены ли ненужные термины и английские слова понятными русскими формулировками;
- понятна ли мысль человеку без знания исследования и профессионального жаргона;
- понятна ли ключевая фраза без картинки и предыдущего слайда;
- не повторяет ли текст метафору, которую уже показывает визуал;
- передаёт ли текст прямой бизнес-смысл вместо красивой загадки;
- складываются ли визуальные строки в нормальную русскую фразу;
- сохраняются ли грамматика и естественный порядок чтения при выделении цифр и слов;
- звучит ли текст естественно вслух;
- так ли мог бы сказать предприниматель другому предпринимателю;
- понимается ли каждая основная фраза с первого прочтения;
- понятен ли основной смысл примерно за две секунды.

Если слайд приходится перечитывать, мысленно переставлять слова, переводить, восстанавливать связь или расшифровывать метафору, он не проходит шлюз и должен быть переписан до дизайна.

Простота не может достигаться искажением факта. При выборе между точной тяжёлой формулировкой и точной понятной формулировкой всегда выбирать понятную.

Сложной может быть мысль. Текст должен оставаться простым. Метафора преимущественно работает в визуале; текст прямо объясняет смысл.

### ФИНАЛЬНЫЙ CTA

Перед финальным сохранением для каждой публикации сознательно выбрать один вариант завершения:

- подписка;
- отправить / поделиться;
- сохранить;
- комментарий;
- диагностика бизнеса;
- без CTA.

Выбор определяется функцией конкретной публикации:

- **подписка** — материал способен привести в блог новых целевых собственников и создаёт ожидание дальнейшего полезного контента;
- **отправить / поделиться** — материал особенно полезен партнёру, руководителю, сотруднику или предпринимателю;
- **диагностика бизнеса** — публикация показывает скрытую проблему, диагностический разрыв или необходимость системного взгляда;
- **сохранить** — материал содержит прикладную модель, проверку, критерии или структуру, к которой полезно вернуться;
- **комментарий** — публикация создаёт содержательную дискуссию и имеет неформальный, небанальный вопрос;
- **без CTA** — любой призыв ослабляет сильный финал.

Не использовать коммерческий CTA там, где он разрушает материал. Не добавлять CTA автоматически и не повторять одну завершающую формулировку постоянно.

Перед выбором проверить `data/posts_history.csv` и чередовать типы CTA. Одна и та же CTA-логика не должна механически завершать серию публикаций.

### FINAL RENDER GATE

Ни одна публикация не получает статус `READY` только потому, что:

- созданы фоновые сцены;
- существует скрипт финальной вёрстки;
- существуют файлы JPG;
- экспорт завершился без технической ошибки.

Финальный Instagram-файл должен содержать уже собранную композицию:

`ВИЗУАЛ + ТИПОГРАФИКА + ЦИФРЫ + ПОДПИСИ + ВСЕ НЕОБХОДИМЫЕ СМЫСЛОВЫЕ ЭЛЕМЕНТЫ`.

Исходная сцена без текста не является финальным слайдом, если смысловая карта предусматривает заголовок, цифру, подпись, пояснение или источник. Файл из папки с исходными сценами нельзя подменять финальным файлом публикации.

После рендера обязательна `POST-RENDER VISUAL INSPECTION`: агент должен открыть и визуально проверить каждый финальный JPG, а не ограничиваться проверкой существования файла, размера или успешного завершения скрипта.

Для каждого слайда подтвердить:

1. Заголовок и предусмотренные смысловой картой элементы физически отрендерены в JPG.
2. Кириллица отображается корректно, без пропавших букв и неподдерживаемых глифов.
3. Текст не выходит за границы, не перекрыт объектами и читается на мобильном размере.
4. Контраст достаточный, визуал и типографика образуют законченную композицию.
5. Размер равен 1080×1350 px и отсутствуют технические артефакты.
6. Элементы читаются в естественном порядке и образуют грамматически нормальную фразу.
7. Язык прост, конкретен и не похож на текст исследования, отчёта или учебника.
8. Ненужные профессиональные термины и английские слова отсутствуют.
9. Главная мысль понятна примерно за две секунды без дополнительного контекста.
10. Разбиение текста ради композиции не заставляет читателя переставлять слова.
11. Каждая основная фраза понятна с первого прочтения и без изображения передаёт прямой бизнес-смысл.
12. Нет абстрактной красивой формулировки, интеллектуальной текстовой метафоры или сложного оборота, который приходится расшифровывать.
13. Главный верхний заголовок имеет достаточно воздуха слева и сверху и не прижат к углу.
14. Для холста 1080×1350 px учтена базовая safe zone главного верхнего заголовка: обычный старт `X ≈ 120–150 px`, `Y ≈ 150–190 px`; критический минимум — примерно `100 px` слева и `125 px` сверху. Координаты не применять механически: при тесной композиции сдвигать ниже и правее.
15. Выполнен `PREVIEW-SAFE TEST`: полный слайд, уменьшенная версия и центральный квадратный crop; заголовок и прямой смысл сохранились.

Если хотя бы один пункт не пройден — перерендерить и снова открыть соответствующий файл. Если программная вёрстка не сработала, не принимать фон за результат: исправить рендер либо остановиться с точно установленной технической ошибкой.
