# Telegram-бот продаж Хасбуллы

Бот проводит подписчика по всей воронке из четырёх продуктов:

1. **«Дорогой час» — 990 ₽.** Оплата в боте → автоматическая выдача материалов.
2. **Личная диагностика — 14 900 ₽.** Оплата в боте → дальше переписка
   с Хасбуллой лично, в его личных сообщениях (не в боте) — там согласуется
   созвон.
3. **Бесплатная диагностика (5 вопросов).** Определяет слабую зону бизнеса
   и подводит к разбору, платной диагностике или сразу к личке.
4. **20-минутный разбор в Zoom — бесплатно.** Сбор контакта и удобного
   времени (или ссылка на самозапись, если она настроена), затем — ссылка
   на личный Telegram Хасбуллы.

Бот отвечает от первого лица («я, Хасбулла»), а не как безликий сервис.
После бесплатной диагностики, записи на разбор и оплаты платной
диагностики бот отдаёт ссылку на личный Telegram-аккаунт Хасбуллы —
дальше переписка идёт напрямую в его личных сообщениях, а не в боте.
Это сознательный выбор: полноценный автоответчик от лица личного номера
(userbot через Telethon/Pyrogram) технически возможен, но нарушает ToS
Telegram для автоматизации личных аккаунтов и рискует блокировкой номера.
Бот — это точка входа и квалификация лида, дальше — реальный человек.

## Установка

```bash
pip install -r requirements-bot.txt
cp .env.example .env
```

Заполните `.env`:

- `BOT_TOKEN` — токен от [@BotFather](https://t.me/BotFather).
- `ADMIN_IDS` — ваш Telegram ID (узнать у [@userinfobot](https://t.me/userinfobot)),
  через запятую, если админов несколько. На эти ID приходят уведомления
  о заявках, оплатах и записях на созвон.
- `HASBULLA_PERSONAL_URL` — ссылка на личный Telegram Хасбуллы
  (`https://t.me/username`). Без неё бот не сможет передать диалог в личку —
  обязательно заполнить перед запуском.
- `PRODUCT1_CONTENT_PATH` — положите файл продукта «Дорогой час»
  (PDF или текст с расчётом стоимости часа и пятью уроками) в
  `data/product_dorogoy_chas.pdf` — бот отправит его автоматически сразу
  после оплаты. Пока файла нет — бот пришлёт админу напоминание вместо
  выдачи заглушки клиенту.

## Приём оплаты — два режима

**Режим 1. Нативная оплата в Telegram (рекомендуется).**
В @BotFather: `/mybots` → ваш бот → `Payments` → подключить провайдера
(например, ЮKassa для РФ). Полученный `PROVIDER_TOKEN` — в `.env`.
Дальше всё автоматически: клиент платит картой прямо в чате, бот сразу
выдаёт продукт или предлагает записаться на созвон.

**Режим 2. Ручной (работает без ожидания одобрения провайдера).**
Если `PROVIDER_TOKEN` пуст, бот показывает реквизиты из
`MANUAL_PAYMENT_INSTRUCTIONS` и кнопку «Я оплатил(а)». После нажатия
админу приходит уведомление с командой подтверждения:

```
/confirm <user_id> <1|2>
```

После `/confirm` бот сам выдаёт продукт клиенту. Это рабочий вариант для
старта, пока не подключён платёжный провайдер — просто на подтверждение
оплаты уходит время администратора, а не происходит мгновенно.

## Запись на созвон

Если задать `BOOKING_URL` (ссылка Calendly/Zoom Scheduler и т.п.) — бот
сразу даёт кнопку для самозаписи. Если оставить пустым — бот сам
спрашивает имя, контакт и удобное время и пересылает админу.

## Запуск

```bash
python -m bot.main
```

Бот работает через long polling — процесс должен быть постоянно запущен
(сервер, VPS, systemd-сервис или Docker-контейнер). Для продакшена
рекомендуется systemd unit с `Restart=always`.

## Данные

Лиды и заказы пишутся в `data/bot_leads.csv` и `data/bot_orders.csv`
(не попадают в git — см. `.gitignore`). Это сырой журнал для контроля:
кто прошёл диагностику, кто оплатил, кто ждёт подтверждения.

## Структура

```
bot/
  main.py         — точка входа, регистрация роутеров
  config.py        — загрузка .env
  catalog.py        — реестр платных продуктов (код/название/цена)
  texts.py           — все тексты бота
  keyboards.py        — inline-клавиатуры
  storage.py            — запись лидов/заказов в CSV
  fulfillment.py          — выдача продукта после оплаты
  handlers/
    start.py    — /start, главное меню
    products.py  — карточки продуктов, запуск оплаты
    payments.py   — обработка нативных и ручных платежей
    quiz.py        — бесплатная 5-вопросная диагностика
    booking.py      — запись на созвон (ссылка или сбор контакта)
    admin.py          — /confirm для ручного подтверждения оплаты
```

## Что донастроить перед запуском в бой

- [ ] Реальный текст и файл продукта «Дорогой час» в `data/`.
- [ ] Платёжный провайдер в @BotFather (или реквизиты для ручного режима).
- [ ] `BOOKING_URL`, если есть Calendly/аналог — иначе запись идёт через
      переписку с админом.
- [ ] Хостинг под long polling (VPS/сервер) — бот не работает как
      статический сайт, ему нужен постоянно запущенный процесс.
